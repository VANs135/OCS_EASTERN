# The Third Winter

第三冬的独立研制目录。目标为 Windows 安装版，首个正式联机剧本为 Scorpion。总体设计在第三冬项目的 `docs/2026-11-17-第三冬与后续OCS桌面游戏研发方案.md`。

## 源码与依赖

| 目录 | 职责 | 可依赖 |
|---|---|---|
| `../../packages/series` | OCS v4.3 通用基础。查表由调用方提供数据。 | 本包 |
| `../../packages/match-core` | 共享对局命令版本及去重。 | 本包 |
| `src/ttw` | 第三冬专规，按机制和剧本拆文件。 | 通规、本作 |
| `src/import` | 第三冬原始格号、格边和算子身份的导入。 | 通规、本层 |
| `src/match` | 第三冬对局接点与待决响应。 | 通规、第三冬、对局核心 |
| `scripts` | 依赖检查及只读资料核对。 | 由脚本消费所需接口 |

复用基线为斯摩棱斯克 `23262ec96b8f`。已提取种子骰、查表与 CRT 查表算法。CRT 由调用方显式提供数据。状态型别只保留所需字段。第三冬资料由本机目录提供，导入检查保留源文件。

仓库根目录的 `npm run check:boundaries` 检查源码依赖。后续规则按能力拆文件，联机持久化、网络传输及界面分别接入。同一命令入口供本机、联机和回放使用，推演与权限检查落在规则或裁判模块。

## 运行检查

- Node.js 22.12 或以上，TypeScript 5.7.3。在仓库根目录执行 `npm ci`。
- 在仓库根目录执行 `npm run check` 检查 TypeScript、工作区依赖与回归。
- 在仓库根目录执行 `npm run audit:data --workspace=@ocs-eastern/third-winter -- <第三冬资料根目录> [单位备份目录]`，核对实际算子引用、瓶中蝎地面部署与开局铁路、战役地图接缝。单位备份目录默认为资料根目录同级的 `DATA备份`。地图读取资料根目录下 `地图数据库/map_hexes_scorpion.json` 和 `地图数据库/map_edges_scorpion.json`。

在安装了 PyMuPDF 的本机，也可从 OCS v4.3 原版图表第 3 页导出 CRT。指定这份表后，核对脚本会在真实盘面执行一次正规战斗，随后跑完双方整理并进入第 2 回合。导出文件留在本机。

```powershell
New-Item -ItemType Directory -Path .\dist -Force | Out-Null
python .\games\third-winter\scripts\export-v43-crt.py 'D:\OCS\规则PDF\通规及表格\OCS_Chartsv4.3.pdf' '.\dist\ocs-v43-crt.json'
$env:OCS_V43_CRT = (Resolve-Path '.\dist\ocs-v43-crt.json').Path
npm run audit:data --workspace=@ocs-eastern/third-winter -- 'D:\war game\OCS各作数据库\OCS第三个冬天'
```

## 小地图桌面预览

```powershell
npm run preview:map --workspace=@ocs-eastern/third-winter -- 'D:\war game\OCS各作数据库\OCS第三个冬天'
```

Windows 预览窗口读取本机原图、算子图与瓶中蝎标定，使用「上一步」「下一步」查看轴心和苏军先后确认部署、离图飞机放置、换回合天气和增援计分。指向标记可读当前值，指向格子可查看盒内单位。开局快照由正式对局命令生成，窗口用于查看结算结果。桌面操作界面与联机仍待接入。

标记保留固定身份。界面根据已提交局面的回合、天气、飞行条件、净胜利分和算子位置重画。校准读取器支持 v3、v4 文件的平移、缩放与盒标签。其他辅助卡可以复用布局和绘制，同一张卡的格号由该卡的状态规则绑定。

- TTW 1.2/Q01 整理起始状态自动改轨判定，1.4a 首次炸桥响应及序列化恢复，1.4d 和 1.5a 渡口资格及容量，1.5b 桥修进度，1.8 战役天气与 1.4b 结冰，2.3a/Q05 Kessel 返回资格，以及 3.2 苏军航空任务限制。
- Scorpion 回合前结算涵盖天气、河岸 VP、突然死亡、支付 1 SP 保留先手、掷骰和选择行动顺序。对局命令会检查当前应答方、盘上补给堆与重复提交。数值对照剧本册第 53 页和小地图天气轨。
- Scorpion 增援接在飞机整备之后。先处理定期到达和固定补给，再掷可变补给、登记 Pax 并抽取和放置 Alert，完成后进入移动阶段。可选部队首次入场扣 5 VP。按 2026-11-17 用户裁定，苏军可变补给以 Scorpion 小地图为准：2–5 为 5 SP、6–7 为 6 SP、8–12 为 7 SP。剧本册第 53 页把 8 列入 6 SP，已记录这一来源差异。
- 整理版提供 1,558 条算子定义。瓶中蝎旧初设与增援引用通过名称或已确认的旧名称映射解析。依据第三冬算子图补齐 59 面移动力颜色，按 OCS 3.1a 读取战斗及移动两面的机动类别。
- 按剧本册第 54–56 页整理瓶中蝎的 155 枚固定地面算子，包括五辆满载编内卡车和两处普通卡车点。`s21.04` 的 3 点由 2 点与 1 点算子叠放。确认部署时由轴心和苏联依次提交，随机抽取的两枚警戒营只抽一次。24 架飞机带着状态进入所选机场或地图外空军盒，三组二选一步损由苏军确认。按剧本册，苏军 `s5.16` 与 `s21.04` 分别为 9 SP 和 10 SP。统一对局记录已跑通初设、首回合固定增援和普通地面移动。自由设置地面模式、卡车初始装载及可选竞标仍待接入。
- 增援导入按剧本册第 55–56 页补入七辆编内卡车和两笔固定 2 SP，区分德军两个步兵师的两步损失。其余到达内容仍需逐项对照原文。战役地图的 11 组接缝交通等级差异已列入检查结果。
- 瓶中蝎地面移动和补给使用同一张六角格地图，共 374 格、1,045 条格边。剧本册第 53–55 页和小地图确定开局轨距、轴心四个和苏军十三个地图边缘补给源。战斗算子进入格后记录铁路控制。无驻军格可由盘面提供已裁定的前线控制状态。
- 补给阶段检查直接追溯、铁路连通、司令部投送与 Kessel HQ，按 OCS 12.6f 处理分散编队的共同来源。无法追溯的单位可由一个或多个盘上补给堆支付，按 12.8 掷骰并由玩家分配断补损失。普通被消灭算子进入死人堆，警戒营回池，轴心断补步损计入苏军净胜利分。
- 移动接入 OCS 12.5c(C) 单算子燃料，合法移动和 1T 扣除在同一条命令结算。编队和司令部燃料、补给延伸队、铁路改轨以及按前线调整空置车站控制仍待接入。
- 预备模式按 OCS 5.4a、5.7 和瓶中蝎剧本册第 53、55 页处理。同格预备单位共用标记，每方六枚。移动阶段可选战斗面或移动面，单枚或同格堆叠按该面的四分之一移动力行进，可在反应或扩张移动环节逐枚释放。编内卡车可进入预备模式。工事限制读取盘面提供的刺猬等级。
