# The Third Winter

中文术语沿用「射击」作为操作总称，下分「炮击」「轰炸」「低空扫射」。OCS 8.0 的 overrun 称为「突袭」。

第三冬的独立研制目录。目标为 Windows 安装版，首个正式联机剧本为 Scorpion。总体设计在第三冬项目的 `docs/2026-11-17-第三冬与后续OCS桌面游戏研发方案.md`。

进度、剩余规则和验收条件见[瓶中蝎研发任务清单](TASKS.md)。

## 源码与依赖

| 目录 | 职责 | 可依赖 |
|---|---|---|
| `../../packages/series` | OCS v4.3 通用基础。查表由调用方提供数据。 | 本包 |
| `../../packages/match-core` | 共享对局命令版本及去重。 | 本包 |
| `src/ttw` | 第三冬专规，按机制和剧本拆文件。 | 通规、本作 |
| `src/import` | 第三冬原始格号、格边和算子身份的导入。 | 通规、本层 |
| `src/match` | 第三冬对局接点与待决响应。 | 通规、第三冬、对局核心 |
| `scripts` | 依赖检查及只读资料核对。 | 由脚本消费所需接口 |

复用基线为斯摩棱斯克 `23262ec96b8f`。已提取种子骰、查表与 CRT 查表算法。CRT 由调用方显式提供数据。状态型别只保留所需字段。第三冬资料由本机目录提供，导入检查保留源文件。

仓库根目录的 `npm run check:boundaries` 检查源码依赖。后续规则按能力拆文件，联机持久化、网络传输及界面分别接入。同一命令入口供本机、联机和回放使用，推演与权限检查落在规则或裁判模块。

## 运行检查

- Node.js 22.12 或以上，TypeScript 5.7.3。在仓库根目录执行 `npm ci`。
- 在仓库根目录执行 `npm run check` 检查 TypeScript、工作区依赖与回归。

## 小地图桌面预览

```powershell
npm run preview:map --workspace=@ocs-eastern/third-winter -- 'D:\war game\OCS各作数据库\OCS第三个冬天'
```

Windows 预览窗口读取本机原图、算子图与瓶中蝎标定，使用「上一步」「下一步」查看轴心和苏军先后确认部署、离图飞机放置、换回合天气和增援计分。指向标记可读当前值，指向格子可查看盒内单位。开局快照由正式对局命令生成。要直接操作对局，请使用下面的本地窗口。

地图上的地面算子、驻场飞机、机场、具象补给与独立标记都按六角格集中排布。每格一页最多四枚，点击格内页码查看其余算子。预备、混乱、断补、部队储备等标记叠在对应算子上，移动和状态变化随对局快照更新。

格心按瓶中蝎小地图原图的水平格线和奇偶列错位计算。完整格的算子以几何格心居中。南北边缘裁切格按保留区域居中并缩小，确保算子和分页按钮留在印刷边界内。

空军演示从同一份实库开局分支。战斗机可在图上机场完成转场，或在扫荡目标格显示「飞」、空战后显示「返」，随后以「停」状态回到地图外空军盒。飞机受损时切换至减员面。

指定 `OCS_V43_BARRAGE` 后，轰炸演示也会更新六角格内的飞机和地面算子。守军的混乱标记随结果出现，飞机返航后从目标格回到地图外空军盒。

指定 `OCS_V43_FACILITY` 后，运输破坏演示会在目标六角格放置所属方的实体标记图，并展示飞机返航后标记仍留在原格。

空运演示显示第 2 回合的可变补给先放入空军盒，再随卸载结果更新到目标机场格的补给堆。地图外补给与盒内飞机遵循同一方的可见性。另有图上空运的受控演示，先清空 `s18.07` 的原守军以验证夺取流程，再让 He.111H 从 `s13.11` 运来 1T。

战斗单位空运演示在同一受控盘面将 Ju.52 和德军 4-4-3 拆分团摆在 `s13.11`。部队到 `s18.07` 卸载后，以移动面用剩余移动力进入 `s17.07`。

「苏军辅助卡」标签页使用本机原图的炮击准备格和恢复轨。设好 `OCS_V43_BARRAGE` 后，三个炮击快照会显示同一枚炮击标记从准备格进入小地图目标格，随后翻面进入恢复格 1。两页切换时保持同一局面。可用以下命令输出辅助卡，再用 `--frame=<从 0 开始的序号>` 指定帧。

```powershell
node --experimental-strip-types .\games\third-winter\scripts\scorpion-map-preview.mjs 'D:\war game\OCS各作数据库\OCS第三个冬天' '--render-aid=.\dist\scorpion-marker-aid.png'
```

标记保留固定身份。界面根据已提交局面的回合、天气、飞行条件、净胜利分和算子位置重画。校准读取器支持 v3、v4 文件的平移、缩放与盒标签。其他辅助卡可以复用布局和绘制，同一张卡的格号由该卡的状态规则绑定。

## 本地桌面对局

在 Windows 从仓库根目录启动一次。后续可双击 `games/third-winter/desktop/start-scorpion.cmd`，直接继续上次本机对局。

```powershell
npm run play:local --workspace=@ocs-eastern/third-winter -- 'D:\war game\OCS各作数据库\OCS第三个冬天'
```

本地窗口使用 Windows 原生地图与辅助卡视图，两人共用一台电脑。左键点单枚算子可选中，点堆叠格内的空白可查看本方算子，按住 Ctrl 点算子可多选。落位时左键点合法目的格。移动时依次点沿途格，再双击终点或点击侧栏的移动按钮。

右键己方算子打开该枚的可用动作，如换面、预备队、加油、装卸、整备、工事和部队储备恢复。选好参战单位或飞机后，右键目标格可发起战斗、突袭、射击或空军任务。菜单只显示第三冬规则引擎接受的动作。回合阶段、骰点和双方应答在侧栏处理。多目标方面军炮击和自定义战斗撤退仍使用折叠的高级规则命令。每次操作结算后更新盘面并自动保存。

进格触发特殊夺取时，原属方在侧栏逐枚分配被夺取的运输点和具象补给。按卡车、马车各自的骰点核对总数。车辆余量、飞机和延补队各选位移落点，可用下拉列表，也可左键点地图上的绿色标记或高亮的本方地图外空军盒。确认后统一结算，对局返回原先的行动。关闭窗口后可恢复待处理的夺取、骰点和剩余行程，面板中尚未确认的选择需重新填写。

默认存档 `dist/scorpion-local/continue.json`。关闭窗口后再次打开会恢复当前阶段、行动方和待决骰点。可使用 `--save=路径` 保留另一局。程序使用仓库 `dist` 内导出的三份 OCS v4.3 图表，也可用上面的 `OCS_V43_*` 环境变量指定本机文件。原图、辅助卡和实际算子从本机资料读取。规则由本机进程结算，存档留在本机。

用同一资料目录执行 `npm run test:local --workspace=@ocs-eastern/third-winter -- <资料目录>` 可核对地图落位、单枚与堆叠选择、右键菜单、双击移动、战斗应答、重掷读档和特殊夺取接续。正式 Windows 安装包、其余桌面操作和联网双人验收仍是后续交付项。

## 当前覆盖

- OCS 2.2 玩家阶段顺序及反应行动方，CRT 算法与固定种子测试。
- TTW 1.2/Q01 整理起始状态自动改轨判定，1.4a 首次炸桥响应及序列化恢复，1.4d 和 1.5a 渡口资格及容量，1.5b 桥修进度，1.8 战役天气与 1.4b 结冰，2.3a/Q05 Kessel 返回资格，以及 3.2 苏军航空任务限制。
- Scorpion 回合前结算涵盖天气、河岸 VP、突然死亡、支付 1 SP 保留先手、掷骰和选择行动顺序。对局命令会检查当前应答方、盘上补给堆与重复提交。数值对照剧本册第 53 页和小地图天气轨。
- Scorpion 增援接在飞机整备之后。先处理定期到达和固定补给，再掷可变补给、登记 Pax 并抽取和放置 Alert，完成后进入移动阶段。可选部队首次入场扣 5 VP。按 2026-11-17 用户裁定，苏军可变补给以 Scorpion 小地图为准：2–5 为 5 SP、6–7 为 6 SP、8–12 为 7 SP。剧本册第 53 页把 8 列入 6 SP，已记录这一来源差异。
- 飞机整备按 OCS 15.1 结算。图上机场每阶段一次、每次 1T，最多整备等级两倍的飞机，并受激活堆叠上限和未抵消敌方 ZOC 限制。双方地图外空军盒免费整备。禁飞天气仍可整备。地图和空军盒上的非激活标记随结果更新。
- 基地转场与战斗机扫荡按 OCS 14.1c、14.2、14.3–14.6、14.11 执行。正常飞行允许本方移动、反应和扩张的移动环节。有限飞行只允许移动阶段。转场进入敌方巡逻区时，由敌方选择是否拦截，并按通规检查防空。扫荡结束后，幸存的扫荡飞机由原属方选择友方落点并转为非激活。空军命令在同一阶段按算子限制使用次数，空战双方选择与骰点随存档恢复。
- 瓶中蝎剧本册第 53 页规定，苏军第 2 航空军活动区为 `s8` 列及以西，第 5 航空军为 `s9` 列及以东，独立航空兵可飞全图，地图外空军盒不产生巡逻区。按本轮用户裁定，图上机场与地图外空军盒之间的转场计为普通航程，战斗机转场成功后保持激活。瓶中蝎小地图全图视为在轴心航空队 HQ 的 60 格指挥范围内，供 TTW 2.2c 的扫荡、轰炸、运输破坏采用。
- 执行层在转场导致激活飞机超出机场容量时打开玩家应答，由机场所属方将超额飞机设为非激活后再继续。飞行任务结算、胜负骰点、防空步损和机场容量检查均由对局状态驱动。
- 按 OCS 10.0、10.2、14.7 接入对地和机场轰炸。普通轰炸在移动、反应和扩张的射击环节执行，与炮击共享同一格每阶段一次的限制。全队被拦截或防空消灭也占用该格的次数。轰炸免费，短程右移要求全部参战飞机从十格内的图上机场起飞。对地轰炸使用防空及空战后的算子面印值，由守方选地形、分配步损。
- 按 TTW 2.2a、2.2f、3.2a 接入低空扫射及反坦克飞机规则。正常飞行时，轴心 Ju.87 或 Hs.129 可单机在移动环节扫射，必须有邻接观察员。扫射可在同一格重复，苏军独立航空兵也受 3.2a 的限制。反坦克飞机只攻击黄底或红底战斗单位，护航的轰炸力不计，防空损失由反坦克飞机承担。
- 按 OCS 10.0c、14.8 接入运输破坏。空战、拦截和防空后使用设施射击表的 `S` 结果放置标记。已有标记的格在再次取得成功时保留原标记。敌方履带和卡车移动进入标记格或相邻格加 1 MP，步行仅在进入标记格时加 1 MP。重叠区每格只加一次，突袭按含加费的地形入格费用判断 3 MP 门槛。敌方整理阶段清除标记。
- OCS 13.3a 的铁路运力计算已接入通规模块。沿线触及一个或多个敌方运输破坏区时，整笔运力费用只翻倍一次，与全程复线的减半相乘。瓶中蝎剧本册第 53、55 页列明双方铁路运力为零。该剧本的铁路仍用于地面顺线移动和补给追溯。
- 补给可从图上友方机场或地图外空军盒装载，送往图上友方机场。按 OCS 14.9e，普通航程按印刷运力，半航程可用双倍运力并按半航程返航，飞越普通航程至多两倍时须在目标机场转为非激活。按瓶中蝎剧本册第 53 页，地图外补给空运默认采用双倍运力。
- 机场每个移动环节允许按 `2T × 等级` 卸载后返航，额外货物可由留场并转为非激活的运输机卸载。按用户裁定，拦截迫使飞机在目标友方机场降落时，未受损飞机的货物完整卸下，受损飞机按减员面重算。按 OCS 12.2，刚卸下的补给当阶段可使用，下一阶段可重新装运。混合补给堆支付费用时优先扣除本阶段卸载的补给。旧存档按当阶段的历史卸载量恢复运输限制，缺少来源记录的部分保守处理。
- 战斗单位空运按 OCS 4.7、5.6、14.9 结算。战斗单位从图上友方机场装载，移动面须为 10 步行 MP 或以下。运输当量按当前 RE 换算，印刷移动面为 1–6 步行 MP 的单位按半额计。部队可与补给混装，受损时由机主选择保留的货物。运输前后的地面移动合计最多半个有效移动力，反应阶段已释放预备队最多四分之一，反应与扩张阶段其他空运部队不得再移动或进攻。
- 《第三冬》战斗单位空投资格按 TTW 2.2d、3.2e 和用户确认处理。只有数据库苏军地面算子 `4301` 对应的第 1 近卫空降旅具备该资格。按 OCS 14.10，在初设或至少提前两回合的飞机整备阶段记录目标格与回合，整备时可延后一回合或取消。该旅只在计划回合的移动阶段实施，落地即结束本阶段移动，当回合豁免追溯补给。瓶中蝎编制未列该旅，相关用例采用受控盘面。
- 双方补给空投免预先计划，沿用飞行条件、航程、空战、拦截和防空。空投表按阶段开始时友军占格和目标地形取值，战斗单位和每 1T 分别检定。苏军骰点减 1，成功落地的补给作为算子放在目标格。敌方战斗单位所在格的空投货物损失。只有敌方非战斗算子时，按 4.8c、9.14 处理，可进格的空降战斗单位执行夺取。
- 按用户裁定，中止空投的货物延用空运损失口径，按损伤后剩余运力处理，超出部分损失。中止航机可在目标友方机场卸载保住的货物。目标没有友方机场时，当前按起飞地点恢复保住的货物，飞机返航落点依通规选择。
- 整理版提供 1,558 条算子定义。瓶中蝎旧初设与增援引用通过名称或已确认的旧名称映射解析。依据第三冬算子图补齐 59 面移动力颜色，按 OCS 3.1a 读取战斗及移动两面的机动类别。

- 具象补给指图上的 SP 和 T，包括运输点装载的补给。抽象补给通过追溯补给源判定，决定单位是否断补。部队储备是单枚单位可用于战斗的储备。

- OCS 12.5 燃料支持三种方法。单算子付 1T，有效至本阶段末。编队付 1 SP，由同一补给堆直拖或同一司令部投送，覆盖从所选来源取得燃料的编队单位。司令部付 1 SP，由本部直拖，为本部及投送范围内的独立单位供油。每阶段首次投油锁定司令部所在格。编队和司令部标记在己方整理清除。普通移动、预备堆叠移动和突袭共用燃料检查。
- 按 OCS 12.2、13.2a/f/g，运输点在同格装载补给，在符合条件的友方格卸载。每次装卸按印刷移动力的 10% 四舍五入，和行军共用移动力。途中可暂停用车载补给供油，再继续行进。换动另一枚算子或开始空军任务会结束该运输点的行进。卸载的补给可立即支用，下一阶段可重新装载。
- 车载具象补给与地图补给堆共用扣账。编内卡车只能供同编队单位拖取，司令部可向该编队投送，编内卡车不能卸到图上。车载补给在供油、射击、战斗补给、补给阶段和飞机整备时分别校验资格。编内卡车上的补给可保留，单位可按 12.10a 动用部队储备。预览使用本机第三冬素材显示燃料和编内卡车装载标记。
- 按 OCS 13.2c、6.1f，同格同型普通运输点在己方移动阶段可合并或拆分。保留运输点总数和已装补给，按最少剩余移动力续走，已分离或已结束移动的点数不能借重组重新移动。现按实库印刷面额校验，实体副本数量待核。
- 按 OCS 12.7，轴心普通卡车或马车的五个空载运输点可在已有追溯补给连接时转换为延补队，各付自身一半印刷移动力。延补队可接力延伸追溯补给和连接前段铁路。盘上补给的拖取、投送和铁路运货各按自身规则处理。主动翻回的运输点可分开移动。按 9.14d，延补队崩溃时由原属方选有追溯补给的落点，位移距离按印刷特殊拖取距离换算为格数，忽略沿途地形和敌军。无合法落点且遭敌方进入时，原地翻回运输点并按 9.14c 检查夺取。主动选择崩溃时须有合法落点。

- 正规战斗依次处理战斗补给、行动值、地形、奇袭、战损、后撤与挺进。战斗中可逐枚动用部队储备并记录低下或耗尽。自己的补给阶段优先恢复部队储备，再用具象补给代替抽象补给。战损更新死人堆，符合剧本条件的轴心损失更新苏军净胜利分。

- 突袭接在移动、反应和扩张阶段的移动环节。接敌路径与每次 3 MP 分别计费，突袭进格费用按原地形和格边核对。战果复用正规战斗的双方应答，奇袭按突袭门槛判定。守军清空目标格后，未撤退的参战单位自动进入，可继续用剩余 MP 行动。
