2026-11-22 · 仓库 `VANs135/OCS_EASTERN` · 默认分支 `main` · 本次核对的引擎基线 `cb81101`。

项目目标是可独立安装、可本地热座、最终可联网双人的桌面 OCS 游戏。本阶段优先完成本地规则引擎和对局接口。仓库可独立检出并开发规则，Windows WPF 开发窗口使用项目方另行提供的地图、辅助卡和算子素材。安装包和联网服务待后续交付。《第三冬》是本仓库首个作品。TFB、克里米亚、列宁格勒等后续作品分别放在 `games/` 下，复用通规和对局基础设施。

## 1. 拉取与验证

需要 Git、Node.js 22.12 或以上及 npm。桌面验收在 Windows 上进行，由 `powershell.exe` 启动 WPF。TypeScript 版本由锁文件固定，按工作区安装。以下命令从仓库根目录运行。

```powershell
git clone https://github.com/VANs135/OCS_EASTERN.git
Set-Location OCS_EASTERN
npm ci
npm run check:boundaries
npm run typecheck --workspace=@ocs-eastern/third-winter
node --experimental-strip-types --test games/third-winter/tests/scorpion-opening.test.mjs games/third-winter/tests/kirovograd-import.test.mjs games/third-winter/tests/campaign-late-turn.test.mjs
```

拿到新版实库后，把 `$ttwData` 改成资料目录。两条审计分别检查 08 初设至首轮飞机整备和 09 数据装配。单次机制开发用小盘面或对应阶段的实库样例验证。全剧本测试由项目方统一安排。

```powershell
$ttwData = 'D:\war game\OCS各作数据库\OCS第三个冬天'
npm run audit:scenario-import --workspace=@ocs-eastern/third-winter -- "$ttwData" 08
npm run audit:scenario-import --workspace=@ocs-eastern/third-winter -- "$ttwData" 09
```

配齐第 5 节的图像和标定后，用仓库中的 v4.3 图表打开 08 瓶中蝎。以下示例指定新的本地档案，默认续局位置在 `dist/scorpion-local/continue-v2.json`，启动设置在同目录的 `settings.json`。当前验收可以从新局开始，暂未承诺旧档迁移。

```powershell
$ttwTables = (Resolve-Path 'games/third-winter/data/scorpion-real-library/tables').Path
$ttwSave = Join-Path (Get-Location).Path 'dist/scorpion-local/handoff-demo.json'
npm run play:local --workspace=@ocs-eastern/third-winter -- "$ttwData" "--tables=$ttwTables" "--save=$ttwSave"
```

桌面入口报缺文件时，先按报错路径比对资料目录、图表和图像。`--tables` 缺省会沿用上次设置，首次缺省从仓库 `dist` 读取。交接时单独交付原始资料目录及数据版本标识，存档和机器设置留在本机。[桌面运行说明](../README.md#本地桌面对局) · [窗口入口](../desktop/local/start.mjs) · [资料加载器](../desktop/local/data.mjs)

## 3. 实现约束

- 按阶段／环节／步（节／环／块）定义流程。为每个规则块记录谁、何时、做什么、在哪里。原文出处、程序实现、用户裁定放在各自的账里。通规流程先对照 `OCS_SOP_CN.pdf`，第三冬增援专规和各方义务按起止窗口嵌入。跨阵营反应及战斗应答区分阶段方和此刻行动方，保存待决应答结束后的返回位置，战斗解决逐步按通规及适用专规推进。
- 一个机制只设一个状态写入口。入口编排、阶段推进、规则资格与结算、视图投影按职责拆分。校验错方、越序、过期版本、库存不足和非法目标后再写入；拒绝命令不改变局面和骰序。预览与正式命令共用合法性判定。命令以 `id`、`expectedRevision` 和动作提交，重试通过回执去重。避免把新增资格、计算和 UI 状态累加到一个会话文件。
- 双方信息按观察方投影。服务端或本地控制器按实际行动方校验命令，保留公开结果与本方可见细节。不同检定各自取新随机数。回放从保存的随机状态还原骰序，重复提交或展开 UI 预览不消耗骰点。
- 单位定义与盘面实例分开，每一枚实体有稳定 ID。地图库按剧本裁出可用格，全景 01 使用 A–D 全图。使用 `terrains_present` 和格边记录判定地形。铁路运输检查边上的己方轨距及阻断条件，沿铁路移动按地面移动处理。只对规则需要的卸货格、补给源和剧本目标等维护控制权，初值由初设战线确定，后续按实际进格更新。
- 桌面一般操作用左键，逐枚点选与再次点击取消，无需组合键。右键菜单提供复杂操作，命令由引擎验证。算子落在六角格中心，模式等状态用小标记叠在单位上。回合、胜利分、天气、飞行条件、预备及其他库存和实体盒以同一对局状态联动。Kessel HQ 从盒移到地图仍是原实体。回合变化和预备储量变化由引擎结算，地图与辅助卡一起刷新。已标定辅助卡按实体盒接入，逐张验收。
- 数据不明时登记原文和缺字段。先由项目方核对或裁定，再把结果接到规则或数据接口。

## 4. 语言、命名和接口规范

### 工程语言与代码风格

| 层 | 当前实现及新增代码要求 |
| --- | --- |
| 规则、会话、导入归一化、视图投影 | TypeScript + ESM。第三冬启用 `strict`、`noUncheckedIndexedAccess`、`noEmit`，目标 ES2022、模块解析 NodeNext。使用能被 Node 类型擦除运行的语法。新增类型常量优先用字面量联合或 `as const`，避免需要运行时转换的 TypeScript `enum`、参数属性等。 |
| 脚本、实库文件 IO、本地桌面桥接 | Node.js ESM `.mjs`。规则计算交由 `.ts` 模块。`.mjs` 入口另做针对性运行验证，第三冬的 `tsc --noEmit` 检查范围为 `src/**/*.ts`。 |
| 当前界面 | Windows PowerShell `.ps1` 承载 WPF，桌面启动与控制器分别在 `start.mjs`、`controller.mjs`。桌面桥接 `protocolVersion: 1` 通过逐行 JSON 传递请求与响应。后续正式桌面技术选型通过适配层接入会话，规则源仍由 TypeScript 模块维护。 |
| 规则回归 | Node 自带的 `node:test` 与 `node:assert`，文件名 `*.test.mjs`。用测试数据或临时目录验证，避免把本地存档或个人机器路径写入用例。 |

- 源码匹配所在模块风格。TS／MJS 通常为两空格缩进、单引号、省略行末分号，文件名用 `kebab-case`，类型用 `PascalCase`，函数、变量及内部字段用 `camelCase`。TS／MJS 的相对导入写实际 `.ts` 或 `.mjs` 后缀，只导入类型时用 `import type`。共享模块用包导出路径，例如 `@ocs-eastern/series/turn`。
- 类型和机器标识用英文。新命令用动词和对象命名，以字面量 `type` 区分动作，例如 `mark-reserve`。桌面请求用 `kind` 区分，例如 `board-left`。维持现有 JSON 字段和大小写。英文 `phaseId`、`actor`、`actionType` 用于分支，中文 `label`、`headline` 和错误提示用于显示；菜单 `key` 为当前视图生成的临时值。
- 外部 JSON 从 `unknown` 进入导入层。对必需字段做形状、取值、唯一性和引用校验，归一到已有类型后交给引擎。数组和索引读取明确处理缺值。需要兼容既有数据时，在输入边界做有来源记录的别名或转换。状态使用同一事实来源，优先复用已有资格检查和结算入口。
- 项目文档、玩家提示及待办默认写简体中文，Markdown、TS、MJS 和新增 JSON 使用 UTF-8。PowerShell 文件沿用所在入口的编码和换行。代码注释写明相关的规则出处、计量单位、适用窗口或例外。引用写清作品、版本、条款和印刷页，有裁定时另列具体条目。版本化文档用仓库相对链接，并保持原文格号、单位番号与数据库引用可检索。

### 数据接入契约

- 单位库正文用 `units`，标记正文用 `markers`，分组资料用 `groups`。当前 TTW v2 加载器校验 `meta.schema`、`meta.game`（`Third Winter`）、`meta.count` 和数组条目数。`formation_groups.json` 是外部编队参考资料，当前 v2 单位加载器从各单位行读 `formation`。保留数据库原字段及大小写，如 `RE`、`MA`、`air_group` 和 `defensiveOnly`。原库的印刷值按外部规范使用字符串，缺值用 `null`，由导入适配器按字段读取并转换。
- 原库用 `faction: "AXIS"`／`"SOV"` 表示阵营，转为引擎 `axis`／`soviet`。按导入器处理无归属的标记。区分原始 `id`、剧本 `ref`、归一后的定义键和实际算子实例 ID。多个副本可共享定义，结算、移动和选取按具体实例 ID。项目保持原文番号作检索，别名只在导入适配层归一。
- 地面算子 `front`／`back` 分别是战斗面和移动面。地面减员用剧本 `steps_lost`，对局内部用 `stepsLost`。原文要求同组两枚算子任选其一减员时，保留 `steps_choose_with` 与原行，接到待决选择后只分配一次损失。飞机的减员、激活和所在地按飞机状态处理。空降等能力以本作规则及数据资格为准。
