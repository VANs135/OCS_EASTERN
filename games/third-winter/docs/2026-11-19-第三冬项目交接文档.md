# 《第三冬·瓶中蝎》接手交接

交接日期 2026-11-19。仓库为 [VANs135/OCS_EASTERN](https://github.com/VANs135/OCS_EASTERN)，代码基线 `f12e45a030234d1f85d8b9e1da093ea211916b96`，首发剧本为《第三冬》剧本 8「瓶中蝎」。接手后的首个任务是把已支持多架飞机的整备规则接到 Windows 机场及空军盒的批量操作。详细范围、顺序与验收见 [后续开发方案](2026-11-19-第三冬后续开发方案.md)。

## 1. 从零启动

需要 Windows、可在终端调用的 Windows PowerShell（`powershell.exe`）、Git、Node.js 22.12 或以上。生成规则图表时另需 Python 和 PyMuPDF。从 PowerShell 拉取基线并安装依赖。

```powershell
git clone https://github.com/VANs135/OCS_EASTERN.git
Set-Location OCS_EASTERN
git switch -c scorpion-refit f12e45a
node --version
npm ci
npm run check
```

基线回归预期为 130 项通过。此检查使用库内测试数据。实库检查和 Windows 窗口还需要下一节的本机资料。

## 2. 项目方交付的资料

| 本机目录 | 启动需要的内容 | 用途 |
| --- | --- | --- |

| 第三冬资料根目录 | `data/scenarios/08-scorpion/setup.json`、`data/scenarios/08-scorpion/reinforcements.json` | 初设与增援。 |

以下路径是配置示例，按接手人的实际位置修改。在仓库根目录执行。已有三份图表 JSON 时放到 `dist`，或修改 `$tableRoot` 指向已准备的目录。需要从原版图表导出时运行三个 Python 命令。

```powershell
$ttwSource = 'E:\OCS资料\第三冬'
$ttwCounterSource = 'E:\OCS资料\DATA备份'
$ocsChartPdf = 'E:\OCS资料\通规及表格\OCS_Chartsv4.3.pdf'
$tableRoot = Join-Path (Get-Location) 'dist'
New-Item -ItemType Directory -Path $tableRoot -Force | Out-Null
```

```powershell
python -m pip install pymupdf
python .\games\third-winter\scripts\export-v43-crt.py $ocsChartPdf (Join-Path $tableRoot 'ocs-v43-crt.json')
python .\games\third-winter\scripts\export-v43-barrage.py $ocsChartPdf (Join-Path $tableRoot 'ocs-v43-barrage.json')
python .\games\third-winter\scripts\export-v43-barrage.py $ocsChartPdf (Join-Path $tableRoot 'ocs-v43-facility.json') --facility
```

首次正常启动会记住三个资料目录。之后可双击仓库中的 `games/third-winter/desktop/start-scorpion.cmd`。

```powershell
node --experimental-strip-types --disable-warning=ExperimentalWarning .\games\third-winter\desktop\local\start.mjs $ttwSource $ttwCounterSource "--tables=$tableRoot"
```

终端输出「瓶中蝎本地窗口已打开」即已启动。左键选择算子、落位及逐格选路，双击目的格提交普通移动，右键算子或目标格查看可用动作。侧栏显示行动方、阶段、战果与待答。默认从 `dist/scorpion-local/continue.json` 续局。用 `--save=路径` 可启动独立测试局。关闭正在使用同一存档的窗口后可重开。若遇资料指纹不匹配，先核对数据版本，保留原档并用新路径测试。

读取入口 [实库适配器](../desktop/local/data.mjs) · [启动器](../desktop/local/start.mjs) · [存档校验](../desktop/local/store.mjs)

## 3. 接手验收命令

在同一 PowerShell 会话中保留上一节的路径变量。三份图表位置对测试和启动保持一致。

```powershell
$env:OCS_V43_CRT = Join-Path $tableRoot 'ocs-v43-crt.json'
$env:OCS_V43_BARRAGE = Join-Path $tableRoot 'ocs-v43-barrage.json'
$env:OCS_V43_FACILITY = Join-Path $tableRoot 'ocs-v43-facility.json'
npm run check
node --experimental-strip-types --disable-warning=ExperimentalWarning .\games\third-winter\desktop\local\smoke.mjs $ttwSource $ttwCounterSource --native-review
node --experimental-strip-types --disable-warning=ExperimentalWarning .\games\third-winter\scripts\audit-data.mjs $ttwSource $ttwCounterSource
```

| 检查 | 基线预期 | 出问题先看 |
| --- | --- | --- |
| `npm run check` | 依赖边界、类型检查与 130 项用例通过 | 在仓库根目录执行。改动的规则应经过实际会话入口。 |
| 实库桌面和原生窗口检查 | 从开局走到移动、战斗和重掷续局，自动夺取、逐枚战损及两格撤退通过 | 缺图或算子别名时先对照资料清单。WPF 需要 Windows PowerShell。测试使用独立临时存档。 |
| 完整资料审计 | 对照地图、单位、初设与增援。固定种子完整局第 8 回合以苏军净胜利分 6 分平局。另核解冻提前结束和突然死亡 | 全量审计还需要两个战役地图 JSON。战役接缝差异按报告核对，瓶中蝎始终读取小地图文件。 |

## 4. 代码从哪里开始读

| 想修改的内容 | 入口 |
| --- | --- |
| 规则或付费结算 | [`scorpion-session.ts`](../src/match/scorpion-session.ts) 对接完整对局命令。按机制进入 `src/match/scorpion-*.ts` 或 `src/ttw/`。 |
| 鼠标操作和菜单 | [`controller.mjs`](../desktop/local/controller.mjs) 接收点击或提交。[`interaction.mjs`](../desktop/local/interaction.mjs) 生成目标和右键候选。[`actions.mjs`](../desktop/local/actions.mjs) 与 [`replies.mjs`](../desktop/local/replies.mjs) 组织阶段操作及应答。 |
| 战果分配和撤退 | [`combat-review.mjs`](../desktop/local/combat-review.mjs) 管理战果和选路草稿，正式结算由会话校验。 |
| 地图、标记和辅助卡 | [`ScorpionLocalPanel.ps1`](../desktop/ScorpionLocalPanel.ps1) 与 [`CalibratedMap.ps1`](../desktop/CalibratedMap.ps1) 渲染窗口。[`src/view/`](../src/view/) 生成六角格布局、地图算子、盒区和实体标记投影。 |
| 保存、续局与后续联机 | [`store.mjs`](../desktop/local/store.mjs) 的存档包包含版本、资料指纹、对局记录和骰序。[`command-log.ts`](../../../packages/match-core/src/command-log.ts) 校验期望版本和命令去重。 |
| 复现真实规则链 | [`scripts/`](../scripts/) 里的 `scorpion-*-example.mjs`，以及 [桌面实库检查](../desktop/local/smoke.mjs) 和 [规则回归](../tests/)。 |

一次操作的链路是窗口事件 → 本地控制器 → 会话校验与结算 → 保存对局记录 → 生成给当前方的盘面。新增复杂操作按机制拆文件，已有命令优先复用，窗口只负责命中、显示候选和提交选择。新增联机客户端时沿用该入口，由服务端负责权威结算。

## 5. 本作已有的关键裁定

| 位置 | 接手时直接沿用的口径 |
| --- | --- |
| 瓶中蝎可变补给 | 苏军两骰合计 8 时，按剧本地图给 7 SP。剧本册第 53 页列 6 SP，这一差异已由项目方裁定。 |
| 瓶中蝎炮击标记 | S8 及以西使用第 2 乌克兰方面军标记，S9 及以东使用第 1 乌克兰方面军标记。仍从规则入口检查 HQ、目标及本剧本允许的使用时机。 |
| 瓶中蝎空军 | 地图外空军盒覆盖整张小地图，可作被夺机场幸存飞机的落点。飞机在图上与盒间转场按普通航程结算，符合规则时继续激活。轴心空军指挥范围覆盖整张小地图。 |
| 第三冬空军 | 苏军独立战斗机的扫荡与低空扫射分别判定，低空扫射禁令适用于苏军飞机。只有苏联近卫军空降兵第 1 旅具有单位空投资格，该旅在瓶中蝎初设和增援表中无编制。 |
| 空运和空投受损 | 任务被迫中止时，货物按飞机受损后仍有的运力结算。飞机未受损时货物保留，超出剩余运力的部分损失。 |
| 守方战斗补给 | 守方以整堆为单位支付具象补给。两个各 1 RE 的单位合计需 2T，仅有 1T 时按整堆规则用部队储备，保留这 1T。按通规 12.10h 区分两个 1 RE 算子和一个多军力算子的余量处理。 |
| 控制权和轨距 | 开局战线用于确定卸车格、补给源及剧本指定点的归属。可记录控制的格由最后经过的单位所属决定。普通铁路格的可用性读取轨距、单位占据与控制区。瓶中蝎双方铁路运力为零。 |
| 自动夺取和撤退 | 进格按规则自动分配夺取及位移，继续已提交路线。读到旧存档停在夺取应答时沿用原骰点。普通战果的选项、步损与撤退仍由执行方选定。 |
| 术语 | 编内卡车、突袭、射击（炮击、轰炸、低空扫射）、延补队崩溃、部队储备、具象补给、抽象补给。 |

规则问题记录“条文与页码、程序表现、用户裁定”三项。斯摩棱斯克用于对照交互和通规实现。第三冬的专规、编号、图表、剧本数据、入场格和用户裁定从本作来源读取。战役专属事项和待核详情继续在《第三冬专规梳理》里维护。

## 6. 交接完成判据

- 接手人在自己的 Windows 环境跑通 `npm run check`、实库桌面检查并启动程序。双方确认资料目录、算子库版本和三份图表的产物位置。
- 接手人能从地图或状态记录复现一次部署、一次移动和一次重新打开续局，并找到批量整备的规则命令、窗体入口与实库示例。
- 项目方收到首个交付回执，包含所用基线、实际运行结果、资料缺项和首项任务的提交位置。后续完成范围由 [开发方案](2026-11-19-第三冬后续开发方案.md) 和 [任务清单](../TASKS.md) 追踪。
