# 通规与专规补全方案

制定日期 2026-11-26。目标：把 OCS v4.3 通规与第三冬专规按实体规则书的分工补全，适用优先级 **剧本 > 专规 > 通规**。分层与覆盖链见[规则三层分工与优先级](2026-11-26-规则三层分工与优先级.md)，已交付批次见[斯摩棱斯克通规移植方案](2026-11-22-斯摩棱斯克通规移植方案.md)，待办底账见[未完成机制清单](2026-11-21-未完成机制清单.md)，专规条款与数据缺口见[第三冬专规梳理](2026-11-11-第三冬专规梳理.md)。

## 1 原则

- 通规进 `packages/series`，只接收规范化事实、返回默认结论；专规进 `src/ttw` 叠加本作例外；剧本以配置/回调/数据覆盖。不在通规里写死作品或剧本例外。
- 开发通规先查 series 与斯摩棱斯克已验收模块，按 v4.3 核对适用范围后提取，记录来源提交并复用用例。国籍例外、库存、具体算子、印刷格号、专规编号与剧本流程由各作品提供。
- 缺实库字段用明确接口表达，以源码＋合成配置验证，不自造库存或规则。数据缺口（G01–G15）由用户维护，装配前相关分支保持阻塞。
- 一个机制一个状态写入入口；命令入口只做编排。每批按机制分批提交，push 前过 `npm run check`（边界＋类型＋单项回归）。
- 条款引用以原文为准：通规章节号对通规 PDF 的章节标题，专规条款号与子条字母对专规梳理 §1 的条款表，斯摩棱斯克模块对其头部的"通规／专规"条文索引。随机事件的普通表与稀有表编号重叠，引用时注明表别。
