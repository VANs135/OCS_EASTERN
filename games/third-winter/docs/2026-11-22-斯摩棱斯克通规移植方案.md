# 斯摩棱斯克通规移植方案

本方案以斯摩棱斯克 `refactor/workbench-decouple` 的 `5603e52` 和第三冬 `main` 的 `01bd523` 为基线。第一批接通全景增援的地面多军力单位整编。后续按模式与 ZOC、地面移动、铁路运输、重建、整备和清理分批实施。各批使用 OCS v4.3 核对通规，由第三冬专规和剧本提供例外。阶段顺序沿用[全回合流程矩阵](2026-11-21-全回合流程矩阵.md)。

当前共享包已有回合换边、先手、补给义务顺序、抽象补给网络、ZOC 投射、突围和射击时机。瓶中蝎已有本地移动、空运、战斗应答、拆分与吸收。全景会话已有回合前和普通增援的执行入口，移动接到了突围环。移植时先接已有共享实现，再提取能补齐全景功能的斯摩棱斯克代码。对应现状见[任务清单](../TASKS.md)和[全景增援阶段流程](2026-11-21-全景增援阶段流程.md)。

## 模块归属

| 层 | 输入与输出 | 改动落点 |
| --- | --- | --- |
| 共享规则 | 接收算子印值、状态、地图连接等已规范化事实，返回资格、费用或结算计划 | `packages/series/src`。使用中立格号和阵营类型。保留来源提交、原函数和规则条款 |
| 第三冬专规 | 提供方面军、RVGK、天气、河道、特殊 HQ、库存及剧本条件 | `games/third-winter/src/ttw`。剧本和数据库由导入／装配层提供 |
| 阶段与盘面结算 | 阶段模块判断阶段、环节和待答方。机制模块调用判定并原子写入盘面、费用和余额 | `games/third-winter/src/match`。`campaign-match.ts` 按命令类型分派，`packages/match-core` 负责版本、回执和去重 |
| 阵营与界面 | 生成本方合法动作、待答和库存，供桌面界面提交命令并重绘地图和辅助卡 | `games/third-winter/src/view`。沿用当前按阵营投影 |

沿用仓库的导入边界。斯摩棱斯克 `workbench.ts` 和 Pinia 切片可用来核对调用时序、交互和已有验收用例。迁入时取规则函数所需的最小类型和事实。一个机制负责一个状态写入入口，跨机制的步骤由所属阶段调用。若同一文件开始同时包办资格、状态写入和视图，应先按职责拆分。规则条件在引擎与预演间共用，避免每层维护自己的判定。具体要求见[开发规范](../../../AGENTS.md)。

## 分批移植与验收

| 批次与来源 | 第三冬接点与适配 | 小盘面验收 |

| **1B 编队与飞机整编**。同文件的 §13.9-2 至 4 | 编队换装接本方增援环，使用编制身份和死人堆中的合法来源，按通规保留模式、标记及编内卡车载荷。飞机合并使用自己的跨阶段命令，检查同格或同一图外区域、机型、数值、状态及减损。当前待决应答继续由会话管理 | 验证合并和换装后算子身份、位置、死人堆与供给记录一致。验证飞机合并在其他阶段也可合法提交 |
| **2A 模式与 ZOC**。`modes.ts` 的模式影响表及 `resolveModeStats`，`zoc-effects.ts` 的 `zocAffectsAction` | 共享模式判定接入移动预算、战斗值和 ZOC。本作算子面、有效标记及阶段作为输入。预备数量沿用已有共享规则和本作库存。剥离斯摩棱斯克战略模式日期。按动作分别查询原始与可抵消 ZOC | 验证战斗面、移动面、战略、预备、DG、进击及被释放预备的有效能力。铁路运输和撤退与卡车补给、整备分别按各自的 ZOC 规则验收 |

| **3 铁路**。`rail.ts` 的 `transportEquivalentOf`、`railCapacityCost`，再提取 `validateRailMovement`、`validateGaugeConversion` | 全景移动／普通移动环／登车、运输、卸货。先迁 §4.7 运输当量及 §13.3a 运量修正，再接合法路径和运力账。用当前格边轨距、卸货格控制、原始敌 ZOC 和运输破坏区。按第三冬配置 Kherson 铁路渡口、铁路炮兵、初始轨距和主动改轨资格。苏军清理自动改轨继续走 TTW §1.2 | 运量按路径结算。测试破坏区翻倍、全程多轨减半及两者叠加。验证反轨距、敌军阻断、非法卸货、运力不足和重复提交。校验铁路运输、抽象补给和河岸战斗各自的渡口约束 |
| **4 补员和重建**。`rebuild.ts` 的余额操作、通规资格及重建计划片段 | 全景增援／重建与整编／选资源、算子和合法落点。沿用已有替换获益，按 TTW §1.7 等配置 Eq 的行动值门槛、Pax、Ally、Air 和特殊替换的留存及花费。轴心、苏军、RVGK、残部与空军走各自落点和池 | 通过普通命令完成扣账和实体去向，双重提交仅记一笔。验证不可重建对象、时限、HQ 和 RVGK 落点、无人可替换时的剩余资源处置 |
| **5 飞机整备与清理**。`air-mission.ts` 的 `refitEligibility`，`cleanup.ts` 的 `planCleanUp` 通规部分 | 两项可各自提交。整备复用现有 `airbase.ts` 容量并从盘面读取 ZOC、支付能力和本阶段已整备记录。各离图盒按本作规定。清理更新本方 DG、进击、燃料和对手放置的运输破坏标记，再调用第三冬的到期义务。自动改轨统一读取清理开始时的快照 | 一次整备只对合格机场、合格飞机扣账。清理只移除应到期标记，苏军 STE 回盒、轨距及辅助卡投影跟随同一状态。各项仅在对应窗口提交 |

**实施顺序**。先交付 1A。1B 依赖已核准的编制和载货字段。2A 可独立推进，2B 与 3 的路径结算依赖地形和格距装配。铁路的纯运量计算可先完成。整备可与 1B–3 并行，清理可在有到期标记和阶段入口后单独接入。全景事件效果、并行回合、方面军姿态和 RVGK 进出继续按[全景待办](2026-11-21-全回合流程矩阵.md#待核与后续-todo)推进。

## 首批交付范围

1A 和 1B 已通过合成盘面的命令和阵营视图验收。正式资料装配与桌面操作仍在任务清单中。[增援接口](2026-11-21-全景增援阶段流程.md#地面多军力单位整编)

1. 从 `planConsolidation` 分出 §13.9-1，接收两枚算子的双面印值、军力和共同前提，返回存留实体、合并后军力及超限损失。以 OCS §13.9 的“两面完全相同”核对规范化字段，单有 `currentRe` 的算子记录不足以执行整编。第一批用合成算子补齐事实，正式数据缺项单列。
2. 将整编命令挂到全景 `reinforcement` 的 `rebuild-consolidate` 环。以 `campaign-reinforcement-phase.ts` 进入该机制，由它的结算模块根据计划更新军力及被移除实体的去向。资格与去向按本作适用规则确认。整编与按替换表支付的重建使用各自命令。
3. 按阵营投影合法配对和拒绝理由。界面提交实例 ID，后端重新读取当前盘面。如果局面版本改变、实例被别的操作消耗或环节已关闭，沿用现有回执和拒绝行为。
4. 复用斯摩棱斯克 `tests/engine/breakdown-consolidation.test.ts` 的通规断言，并验证第三冬正常命令入口、RVGK 例外和辅助卡或盘面状态一致。首批验收只涵盖 1A。

## 2A 模式与控制区交付记录

| 原文 | 谁／何时／做什么／在哪里 |
| --- | --- |
| OCS §4.5、§5.9c | 可攻击且未断补的战斗面单位，在敌方行动取盘面快照时，向自身相邻格投射 ZOC。进击保留原有控制区。 |
| OCS §5.7、§5.8、§5.9、§5.10 | 拥有对应标记的单位，在移动、战斗和炮击环计算印值时，使用当前面和生效标记的修正。预备释放后恢复原朝向，反应与进击移动环分别使用半额与全额 MA。 |
| OCS §4.5a–b、§9.12e | 轮式移动、抽象补给及飞机整备按动作检查目标格的可抵消 ZOC。切入预备及撤退仍检查原始敌方 ZOC。撤退的 DG 与军力损失由撤退步结算。 |

**实现**。从斯摩棱斯克 `5603e52` 的 `modes.ts`、`zoc-effects.ts` 提取模式效果表、移动倍率和动作条件，放在共享包的 `modes.ts`、`zoc.ts`。瓶中蝎适配当前面、标记和预备释放状态，移动、正规战斗、突袭、炮击和控制区取同一套效果。轮式移动继续读本阶段可作抵消的单位，抽象补给的轮式与铁路追溯按相同的抵消规则使用供给盘面，飞机整备单独按其动作取值。全景的突围路径读取盘面当前面、DG 和断补状态，当状态缺少印刷面或断补事实时沿用规范化算子档案。天气、地形、各方的模式标记库存及突围专规则由第三冬处理。

**范围**。战略模式的数值和 ZOC 条件已有共享判定。战略模式切换、移动终点补给、铁路运量、改轨与全景重建的命令接入仍在后续批次。轮式移动对抵消单位的阶段内 MP 处理，随 2B 路径和移动状态迁移复核。

**用户裁定**。本批沿用已记录的第三冬裁定，通规模型以 OCS v4.3 为依据。

## 每批交付检查

1. 记录三类依据。原文记录通规／专规落点和「谁／何时／做什么／在哪里」。实现记录来源提交、提取函数、接口、状态写入点和用例。用户裁定按作品和剧本范围记录。
2. `npm run check:boundaries` 与 `npm run typecheck -w games/third-winter` 通过。运行迁入的通规断言和第三冬相关的单项用例。源端 7 组相关测试曾运行 243 项并通过，移植后另以第三冬命令、盘面和投影验收。全剧本测试由用户统一安排。
3. 验证错方、越序、缺失事实和旧版本命令不起效。盘面、账本、实体库存和回执同批提交。若某机制需要掷骰，每个独立检定取新骰并记录，同一命令重试沿用原回执。
4. 每批按机制提交并推送。任务清单分别记录通规提取、第三冬命令接通、正式资料装配和界面验收。数据库由用户维护。缺失字段写清来源和影响，由数据装配提供后再启用相关分支。

后续 TFB、克里米亚和列宁格勒可在自己的 `games/` 作品目录调用共享包，提供各自的地图、算子、剧本及专规。斯摩棱斯克若后续接入同一共享包，再单独用它的回归测试替换原有函数调用。
