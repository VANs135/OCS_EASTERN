# 斯摩棱斯克通规移植方案

本方案以斯摩棱斯克 `refactor/workbench-decouple` 的 `5603e52` 和第三冬 `main` 的 `01bd523` 为基线。第一批接通全景增援的地面多军力单位整编。后续按模式与 ZOC、地面移动、铁路运输、重建、整备和清理分批实施。各批使用 OCS v4.3 核对通规，由第三冬专规和剧本提供例外。阶段顺序沿用[全回合流程矩阵](2026-11-21-全回合流程矩阵.md)。

当前共享包已有回合换边、先手、补给义务顺序、抽象补给网络、ZOC 投射、突围和射击时机。瓶中蝎已有本地移动、空运、战斗应答、拆分与吸收。全景会话已有回合前和普通增援的执行入口，移动接到了突围环。移植时先接已有共享实现，再提取能补齐全景功能的斯摩棱斯克代码。对应现状见[任务清单](../TASKS.md)和[全景增援阶段流程](2026-11-21-全景增援阶段流程.md)。

沿用仓库的导入边界。斯摩棱斯克 `workbench.ts` 和 Pinia 切片可用来核对调用时序、交互和已有验收用例。迁入时取规则函数所需的最小类型和事实。一个机制负责一个状态写入入口，跨机制的步骤由所属阶段调用。若同一文件开始同时包办资格、状态写入和视图，应先按职责拆分。规则条件在引擎与预演间共用，避免每层维护自己的判定。具体要求见[开发规范](../../../AGENTS.md)。

## 首批交付范围

1A 和 1B 已通过合成盘面的命令和阵营视图验收。正式资料装配与桌面操作仍在任务清单中。[增援接口](2026-11-21-全景增援阶段流程.md#地面多军力单位整编)

3. 按阵营投影合法配对和拒绝理由。界面提交实例 ID，后端重新读取当前盘面。如果局面版本改变、实例被别的操作消耗或环节已关闭，沿用现有回执和拒绝行为。

### 首次炸桥应答

**原文**。TTW §1.4a，第 2 页。轴心在首个苏军战斗单位移动进完好伏尔加级河桥任一端格时，立即决定是否炸桥。炸桥自动成功。此次保留后结束该桥的炸桥机会。§1.5b 规定修复桥此后不能再炸。

**实现**。移动阶段／普通移动环／进格应答步。`campaign-ground-march.ts` 在合法进格后写入已花 MP、当前位置及已用跨越量，并暂停路线。`campaign-march-response.ts` 接收本次所有候选桥的轴心决定。`blow` 指定炸掉的桥，当前名单中的其余桥永久保留。公开地图从已结算决定投影炸桥标记。轴心只收到本次桥清单，苏军改道时只收到本方当前行军单位和剩余 MP。有合法后缀时自动恢复。若原路径失效，苏军以原有余额预演改道或结束移动，战略模式仍检查终点追溯补给。各次决定均沿用对局版本和回执，并且无需掷骰。

**范围**。已用合成盘面验证仅普通地面移动触发的情形、同格多个桥、连续两次应答、已经跨桥才触发时的 RE 余额和改变桥况后的战略终点检查。正式桥网装配、其他进格来源及桌面控件仍在后续任务中。

### 浮桥单位工程

| 原文 | 谁／何时／做什么／在哪里 |
| --- | --- |
| TTW §1.5–1.5a，第 2–3、35 页 | 本方战斗面浮桥单位，包括朝战斗面的 DG，在整个移动阶段留在邻接伏尔加级河的格。普通移动环可免费部署渡口并立即开放，也可撤收本阶段尚未使用的渡口。已部署的渡口及本阶段工程承诺限制该单位移动。 |
| TTW §1.5b，第 3 页 | 本方在被炸桥任一端修桥。四个合格移动阶段累计完成后，在下一次本方移动阶段开始时开放修复桥。敌战斗单位邻接阻止累计，敌可攻击战斗单位占领任一端使进度清零。施工中断保留既有进度，多枚浮桥单位同桥仍只计一次。 |

**实现**。移动阶段开始时进入突围环之前，保存规范化浮桥单位的起始位置并开放到期桥梁。普通移动环接收渡口和施工命令，同一浮桥单位可同时安排渡口和修桥。未取消的修桥安排在后续合格起点继续。普通移动以后由空／海军射击环结束命令核对配置所报的义务，才累计这一阶段并进入补给阶段。进格时同步结算敌占导致的进度清除。公开视图读同一份普通渡口、施工进度及修复桥资料，本方工程指令只投影给当前行动方。每条渡口实际航渡与原有 3 RE 跨越账一起提交。

**实现约定与待核**。若两枚有效友方渡口都能完成同一次航渡，按标记 ID 固定选择一枚记入使用账。已有炸桥等独立通道能完成跨越时，不记作使用渡口。进度归当前施工方，跨方接手缺少明确条文，保留待核。普通河流的浮桥小径桥、Kherson 铁路渡口、全景射击及战斗导致的撤退或损失仍待接入。施工验收使用合成盘面和明确提供的浮桥资格、桥况及射击收尾义务。
