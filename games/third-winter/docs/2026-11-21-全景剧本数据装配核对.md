# 第三冬全景剧本数据装配核对

首个核对对象是剧本 01「第聂伯河之战」。审计用本机第三冬新版算子库、A–D 地图数据库和剧本目录的初设、增援、胜利资料。核对命令从仓库根目录执行，省略第二个参数时使用剧本 01。

```powershell
npm run audit:campaign --workspace=@ocs-eastern/third-winter -- '<第三冬资料目录>' 01-dnepr-battles
```

命令会输出 JSON 报告。返回值 1 代表有输入未通过本次核对或还缺规则化数据。报告中的初设和增援条目位置从 1 开始计数，可直接定位源数组。

用户确认 01 号剧本使用 A–D 全图。范围查询纳入 8,680 个去重后的图内格。接缝两侧的印刷格号可指向同一格。其他剧本按各自范围配置，尚未接入的范围报告为 `unconfigured`。审计把已有地图格却落在剧本范围外的部署单独列出。

| 项目 | 已核到 | 下一步 |
| --- | --- | --- |
| A–D 地图 | 8,928 条源格按 248 对互指接缝归入 8,680 个格号索引。27,564 条源边归出 25,653 对相邻格。493 对有多条来源，8 对存在字段差异。1,417 条边只有一端，无悬空引用 | 确认哪些开放边属于可入场接口。8 对差异涉及 4 对轨道等级和 4 对湖边字段。另有 11 个源接缝组的交通字段不一致，`SEAM1047` 包含两对不同端点。河流仍为 `pending` |
| 初设 | 690 条均可定位，667 条非标记记录唯一匹配本方定义。另有 2 条随机抽取的落位格可定位 | 23 条标记记录含减员与 RVGK，需要按原版初设核对它们附属的单位或独立状态。随机抽取还需接通正确的池及消耗规则 |
| 增援与撤编 | 273 组，共 587 条命名记录，其中 580 条非标记记录唯一匹配本方定义 | 7 条标记记录及 10 条文本记录须转换成规则动作。按相关 HQ、机场、RVGK、撤编、入场或补充库存逐类建命令 |
| 胜利条件 | 数据指向战役 §5.0 | 补录并核对计分地点及结果档位 |

地图索引提供 `neighbors(hex)` 查询相邻格，以及 `connection(from, to)` 查询该对格子的所有源记录和冲突字段。两端顺序可交换，也可使用接缝别名或带前导零的印刷格号。相邻关系描述几何连接，移动与补给另按确认后的格边规则校验。不同端点对保留独立连接。原资料继续只读，场景创建仍需装配初设、地图边的实际通行状态、阶段日历、增援与胜利判定。
