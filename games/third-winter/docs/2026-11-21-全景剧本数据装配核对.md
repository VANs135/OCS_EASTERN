# 第三冬全景剧本数据装配核对

首个核对对象是剧本 01「第聂伯河之战」。审计用本机第三冬新版算子库、A–D 地图数据库和剧本目录的初设、增援、胜利资料。核对命令从仓库根目录执行，省略第二个参数时使用剧本 01。

```powershell
npm run audit:campaign --workspace=@ocs-eastern/third-winter -- '<第三冬资料目录>' 01-dnepr-battles
```

命令会输出 JSON 报告。返回值 1 代表有输入未通过本次核对或还缺规则化数据。报告中的初设和增援条目位置从 1 开始计数，可直接定位源数组。下表记录先前整库审计，当时读取的 `map_edges.json` 为 17,263,309 字节。新版格边文件为 15,796,726 字节。本轮单独加载新版地图，A–D 仍为 8,680 个图内格和 25,653 对相邻格，悬空端点为 0，`D14.03` 可解析。单位和剧本数据待修正后再一起核对。

用户确认 01 号剧本使用 A–D 全图。范围查询纳入 8,680 个去重后的图内格。接缝两侧的印刷格号可指向同一格。其他剧本按各自范围配置，尚未接入的范围报告为 `unconfigured`。审计把已有地图格却落在剧本范围外的部署单独列出。

| 项目 | 已核到 | 下一步 |
| --- | --- | --- |
| A–D 地图 | 8,928 条源格按 248 对互指接缝归入 8,680 个格号索引。27,564 条源边归出 25,653 对相邻格。493 对有多条来源，8 对存在字段差异。1,417 条边只有一端，无悬空引用 | 确认哪些开放边属于可入场接口。8 对差异涉及 4 对轨道等级和 4 对湖边字段。另有 11 个源接缝组的交通字段不一致，`SEAM1047` 包含两对不同端点。河流仍为 `pending` |
| 初设 | 690 条均可定位。667 条非标记记录已装配为带源行号、定义 ID 和统一格号的待部署记录，其中 16 条保留了来源明示的减员数。另有 2 张待抽取指令 | 23 条标记记录仍待处理，其中 22 条是减员标记占用部队记录，另 1 条为 RVGK。随机抽取还需接通正确的池及消耗规则 |
| 增援与撤编 | 60 个回合有增援组，共 273 组、597 条明细。580 条非标记引用唯一匹配本方定义。其中 567 条可归入到达、撤编或转死人堆 | 7 条标记、10 条文本、13 条渠道待核和 1 个空组。已归类条目的数量、减员、落位与库存等结算仍需按来源逐项接入 |
| 胜利条件 | 数据指向战役 §5.0 | 补录并核对计分地点及结果档位 |

地图索引提供 `neighbors(hex)` 查询相邻格，以及 `connection(from, to)` 查询该对格子的所有源记录和冲突字段。两端顺序可交换，也可使用接缝别名或带前导零的印刷格号。相邻关系描述几何连接，移动与补给另按确认后的格边规则校验。不同端点对保留独立连接。原资料继续只读，场景创建仍需装配初设、地图边的实际通行状态、阶段日历、增援与胜利判定。

初设装配为每条待部署记录保留算子类型和源行号。审计返回装配数量、减员解析结果、待核标记和随机抽取指令。减员从该行明确的来源字段读取，含义不清或超出单位容量时列为待核。待抽取指令带阵营、格号和池名，供后续开局模块执行。[初设装配入口](../src/import/campaign-setup.ts)

## 增援阶段接口

增援阶段下按回合、行动方查询本方记录，保留源数组顺序、日期、渠道、备注以及组和明细的位置。已识别的块是到达、撤编和转入死人堆，实库分别归类 376、175 和 16 条。到达渠道保留 HQ、机场、RVGK 等限制信息。指定格 `D14.03` 经过地图索引和剧本范围核验。是否可在某个 HQ 或机场落位，须由执行时的盘面和规则决定。[增援导入](../src/import/campaign-reinforcements.ts) · [阶段查询接口](../src/ttw/campaign/reinforcement.ts)

报告的 `reinforcement.firstTurn` 展示双方首回合的读取结果，`reinforcement.pendingOrders` 列出待核位置。已归类状态表示识别了来源记录的处理类别，数量、减员、标记库存和玩家应答仍须由具体命令结算。
