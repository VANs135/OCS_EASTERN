# 《第三冬·瓶中蝎》后续开发方案

基线 `f12e45a`，核对日期 2026-11-19。第一阶段完成瓶中蝎的 Windows 本地双人整局操作，随后交付 Windows 安装版和互联网双人联机。第三冬战役与 TFB、克里米亚、列宁格勒各自在共享规则和对局协议上接入。

## 1. 当前可以交付给接手人的基线

Windows 本地热座已能启动和续局。地图支持左键点算子、落位和选路，右键按算子或目标格列动作。已有开局、增援、地面移动、战斗、逐枚战损、地图撤退、大部分空军与补给的基础操作。进格特殊夺取自动结算并继续原路线。回合、天气、飞行条件、胜利分和已接辅助卡标记跟随局面更新。

瓶中蝎规则层已用实库脚本覆盖八回合终局、首次解冻提前结束和突然死亡。130 项回归以及原生窗口的启动、重掷续局、自动夺取和撤退测试已有通过记录。当前交给玩家的是本机开发版，正式的整局鼠标验收、可分发 Windows 安装包及两地联网仍列在后续批次。[任务清单](../TASKS.md) · [游戏功能对照](2026-11-19-斯摩棱斯克与第三冬游戏功能对照.md)

按顺序完成前三项，再进入撤退与空运的扩充。每个条目从现有规则命令出发，落到玩家可完成的流程和可重复的验收盘面。

### 第一项可直接开工的范围

- **规则入口**沿用 `refit-aircraft`，一次传入同一基地的 `unitIds`。图上基地传 `hex` 和 `dumpId`，地图外空军盒用 `off-map-air`。规则层统一校验阵营、非激活状态、阶段、整备额度、激活容量、控制区和付款。
- **桌面入口**从现有机场或地图外空军盒开始，面板只列该基地本方非激活飞机。图上基地出示可付款来源，合计费用显示 1T。确认后同步牌面状态、补给余额和阶段待办。建议把选机和付款草稿放独立模块，由窗口负责接收点击。
- **验收盘面**先复用已在实库运行的整备演练，再做窗口组合操作。覆盖一项成功、一项超额拒绝、一项无补给来源拒绝，以及关闭窗口后仍只有一次扣账。

| 互联网联机 | 在同一规则入口上接入邀请房间、席位、服务端结算、持久化、按席位投影视图和重连。 | 两台不同网络的 Windows 电脑从安装入房打到终局。分别模拟指令已送达但回执未到、等待对手应答和服务重启，恢复后不重复扣账、不重掷，双方结果一致。 |

联机批次先验证一条完整命令链。客户端发送对局号、唯一命令 ID、期望局面版本和动作，由服务端验证席位、行动方和版本，再调用第三冬会话结算。服务端持久化命令结果和骰序，保存成功后返回回执，并按席位投影可见内容。旧客户端重连时按版本追赶或重新取快照。服务端的具体技术选型由两地联机和恢复验收结果决定。

## 4. 分层和协作方式

- 第三冬规则与本作裁定位于 `src/ttw`、`src/match`，系列规则放 `packages/series`，对局版本与去重放 `packages/match-core`。桌面从会话读投影并提交动作，服务端复用同一结算入口。
- 每个复杂操作按机制拆文件，界面只负责显示候选和收集选择。斯摩棱斯克适合参考点击分派、阶段门槛、候选清单和人工验收方法。第三冬的任何具体判据和数据从本作原文、书表、数据库和已确认的裁定取值。
- 玩家操作沿用左键选子、选格、选路，右键发起复杂动作，侧栏显示待答与结果。棋盘算子以格心为基准，模式标记叠在算子上。回合、天气、飞行条件、胜利分和辅助卡上的实体标记都从最终对局状态更新。
- 每个交付项附可复现的剧本、阶段、行动方、输入及预期结果。记录对应规则出处、实现位置与用户裁定。数据缺口登记原文页码和缺失项，等待权威资料或裁定。
- PR 说明注明基线、完成范围、通过的检查和已知未覆盖，加一组能复现的新入口操作。补验证时优先复用现有实库测试盘面。涉及双方应答、随机数、存档迁移和实体标记位移时补相应回归。
