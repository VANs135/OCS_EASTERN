## 核心结论

**1. 分层是干净的，而且被脚本强制。** 97 个 `.ts`（7,267 行）零第三方运行时依赖，只用 Node 内置模块；方向单向：`series`/`match-core` → `import`（只读资料）→ `ttw`（专规原语）→ `match`（命令结算）→ `view`（纯投影）→ `desktop`（唯一 IO）。`src` 内无运行时循环依赖（唯一反向边是 `import/scorpion-arrivals.ts:2` 的 type-only import）。`view` 之所以"纯"，是实测过的：零 fs、零 `Math.random`、零 `process`。

**2. 联网所需的协议骨架已经在了，缺的是服务。** `packages/match-core/src/command-log.ts` 的 `acceptCommand` 已实现：`(side, id)` 幂等去重、`expectedRevision` 乐观并发、receipts 存**完整 action 原文**、revision 单调递增。文件头注释直接写着设计约束"先原子落盘再回执、调用前先解析已认证席位"。接权威服务不需要重做协议。

**3. 真正卡人的不是架构，是三件环境事。** 桌面写死 `spawn('powershell.exe')` + WPF（`desktop/local/start.mjs:55`）；仓库里**一份资料、一张表都没有**（`dist/` 被 gitignore，`ocs-v43-*.json` 数量为 0，三张表要用 PyMuPDF 从本机 PDF 第 3/4 页抽）；存档只认 `version:1` + 资料指纹。新接手的人第一小时大概率卡在第二步，不是看不懂代码。

**4. `src/match` 是作品层，不是共享层。** 54 个文件里 52 个以 `scorpion-` 命名，27 个按值 `import ../ttw/scorpion`。接 TFB/克里米亚/列宁格勒只能"复制骨架 + 重写专规"，可复用的只有：`series` 的通规原语（表算法只吃调用方给的 `TableLike`/`CrtLike` 最小结构）、`match-core` 的协议、`view/calibrated-surface.ts` 的标定思路、桌面壳的形状。

**5. 共享层有一处会绊住新作品。** `Side = 'axis' | 'soviet'` 写死在 `packages/series/src/state-types.ts:1`（third-winter 内 63 个文件用到 `Side`），八阶段序列写死在 `turn.ts:3-16`；而边界脚本对 `packages` 的白名单是**空集**，共享包之间既不能用包名、也不能用相对路径互相引用——想新增第三个共享包来放"多阵营/多阶段"，当前规则下做不到。README 写的"共享包之间按职责单向引用"与脚本实际行为不一致。

## 数据流一条链（细节与行号在文档第二节）

`start-scorpion.cmd` → `desktop/local/start.mjs`（读 `dist/scorpion-local/settings.json`；首次必须传资料目录，实测会抛"首次启动请传入第三冬资料目录"）→ `data.mjs:12 loadLocalScorpion` 装配 `{assets, setup, model, board, fingerprint}`（地图 `地图数据库/map_hexes_scorpion.json`、算子 `units.*.json`、剧本 `data/scenarios/08-scorpion/`、标定、三张 `ocs-v43-*.json`，`data.mjs:39` 算 sha256 指纹）→ `controller.mjs:14 openLocalScorpion`（`store.mjs:25` 建 `.lock`、`store.mjs:80` 校验存档或新建）→ `start.mjs:55` spawn PowerShell 起 WPF → 面板 `ScorpionLocalPanel.ps1:52` 每次请求先贴 `revision` 再写 NDJSON → `controller.mjs:72 dispatch`（`:75` revision 不符即拒；菜单用 `controller.mjs:32 available()` **拿真引擎的异常当"不合法"**，预览用假 id）→ `controller.mjs:26 run` 每步构造 `{id, expectedRevision, action}` 调 `submitScorpionSession` → `scorpion-session.ts:142`（门禁链 → 待决优先 → 约 40 分支 `switch` → `scorpion-reroll.ts:48` 处理"命令中途要掷骰"的 `OfferRoll` 挂起 → `scorpion-phase-occupancy.ts` 刷新占用）→ `command-log.ts:24 acceptCommand`（去重/版本/落 receipts）→ `controller.mjs:43` 落盘（`store.mjs:6` tmp+rename 原子写）→ `controller.mjs:179 render` + `view/*` 出帧 → 回 stdio 重绘。`commit` 里还有一道 `verifyRngState(rng)`（`rng.ts:194`），失败抛"骰序无法保存"。

## 扩展点：三个接入面都在现成的纯净边上

- **新作品**：新建 `games/<title>/src/{ttw,import,match,view,desktop}`，`check-boundaries.mjs` 按 `games/*` 通配会自动纳入，`match-core` 已对 `Seat extends string` 泛型，都不用改。**但要先决策 `Side` 与阶段序列怎么处理**（泛化共享包 vs 映射到 axis/soviet 两槽位）。第一个可跑目标建议走"无桌面、纯脚本驱动"，用 `scripts/scorpion-demo-commands.mjs` 那种范式先验专规。
- **联网**：新建服务端进程，只 import `@ocs-eastern/match-core` + `src/match/scorpion-session.ts`（**绝不要 import `desktop/local`**——这就是客户端/服务端切分线）。断线续局有现成抓手：`reroll`/`capture`/`combat.retreat`/`airMission`/`barrage`/`airfieldCapacityChoice` 全是显式待决状态（`replies.mjs:17-35` 的优先级链就是清单）。**两处缺口**：无 replay 驱动（`rng.ts:182 replayFrom` 只重建骰序、不重建状态），所以"重连追赶"要补；迷雾只在 `scorpion-boxes.ts:28` 的 `viewer` 里生效、且只藏离图空中盒，`scorpionMapStacks` 没有 viewer 参数、双方算子全画——双人联网必须先做可见性。
- **回放**：新建 `src/match/scorpion-replay.ts`，用 `receipts.reduce` 逐条重放再与存档 state 深比较，是最便宜的回归网。**跨版本回放现在做不到**：存档以 `fingerprint` 为前提、`version` 只有 1、没有迁移代码。另外 `render` 现在在 `desktop/local/controller.mjs:179`（带 `.mjs` 与 UI 偏置），回放要去桌面化得先把它提纯到 `src/view`。

## 风险：3 个 P0、6 个 P1、8 个 P2（完整表含触发条件在文档第四节）

- **P0** ①桌面端仅 Windows（触发：在 macOS/Linux/CI 跑 `play:local`，或 `ExecutionPolicy` 被组策略锁）；②仓库无任何资料与三张表（触发：全新 clone / 换机器 / CI）；③存档只认 `version:1` + 资料指纹（触发：改任何资料文件、改 state 形状、换资料目录）。**动手改资料前请先备份 `dist/scorpion-local/continue.json`。**
- **P1** ①共享层把阵营与阶段写死；②共享包之间无法建立依赖；③联网缺重连追赶与隐藏信息；④`desktop/local`（1,563 行）与 `scripts`（1,470 行）完全不参与类型检查（`tsconfig` 的 `include` 只有 `src/**/*.ts`，根目录没有 tsconfig、没有 CI、两个共享包也没有自己的 `typecheck`/`test` 脚本）；⑤`scorpion-session.ts` 411 行单点耦合（门禁+40 分支+重掷拦截+占用都在一个函数里，并行加命令会撞车）。
- **P2** 地图几何与 39 处格号硬编码（如 `scorpion-phase-flow.ts:57` 的 `s22.08`）；边界脚本对 `.mjs` 是盲区（我实测在 `desktop/local` 里造跨作品 import，脚本照样打印 "Source boundaries passed."）；本地锁在网盘/多实例下不可靠；PDF 导出脚本对版本极敏感；测试全在作品目录、共享包无自有测试。

**关于类型安全别误判**：`any` 0 次、`@ts-ignore`/`@ts-expect-error`/`@ts-nocheck` 各 0 次，`strict` + `noUncheckedIndexedAccess` 全开、`tsc` 零错误——但**被检查的那部分干净，而近一半代码（1,563 + 1,470 行 `.mjs` 加 703 行 PowerShell）不在检查范围**，恰好是 IO、存档、菜单拼装这些最易错的地方。

建议的接手顺序：①先把资料目录与三张表拉齐、跑通 `npm test` 与 `audit:data`（绕开 Windows 依赖）；②再读 `scorpion-session.ts` 的 `switch` 认全动作面；③按上表决定 `Side`/阶段序列的处理方式；④最后才动桌面与联网。
