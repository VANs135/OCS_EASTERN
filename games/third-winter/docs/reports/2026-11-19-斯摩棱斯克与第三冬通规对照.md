## 核心结论

**第三冬缺的不是「玩法」，而是「通规的公共层」。** 补给追溯、燃料、预备、损耗、战斗、炮击、空运在 `games/third-winter/src/match/` 里都已实现且质量不低，但都是**逐条内联重写**，没有下沉到 `packages/series`。真正的缺口在 `packages/series/src`（14 个顶层文件共 801 行）：模式矩阵、ZOC 投射、战斗损失分离、铁路移动与改轨、拆解/整合、合法性与 SOP 校验，在这层**一个文件都没有**。

判定证据（可复现）：`grep -rl` 关键词于 `packages/series/src` 与 `games/third-winter/src` **均 0 命中** —— `legality` / `breakdown` / `consolidation` / `entrain` / `patrolZone` / `SOP_STEPS` / `stratMode` / `airstrip` / `ReplHoldings` / `canAffordRepl` / `gaugeConvert` / `dumpBlow` / `overrunStack` 全部为零。厚度对比同样直白：`series/attrition.ts` 13 行 vs smol `tables/attrition.ts` + `rules/supply-phase.ts` 787 行；`series/air-transport.ts` 8 行（只有三个模式键）vs smol 四个模块共 545 行。

**已有零星提取的部分质量过关，是「扩面」不是「重做」**：`rng.ts` 与 smol `engine/rng.ts` 逐行等价；`tables/lookup.ts`、`tables/crt.ts`、`tables/barrage.ts` 形态一致甚至更好；`trace-path.ts` 的 Dijkstra 是 smol `trace-supply.ts` 距离内核的干净抽象。

**最大的架构冲突是「数据归属」**：smol 引擎内嵌 `@/data` 的 `rulesConstants` / `chartsTables` / `mapLayers`，`packages/series` 一律「查表由调用方提供数据」（`CrtLike` / `BarrageTable` / `GroundMap<Edge>` / 注入 `RollDie`）。所以 **算法可搬，常量与表必须留在 `games/third-winter`**。这条决定了绝大多数工作项的落点，也是 `check-boundaries.mjs`（`games/*` 只能 import `@ocs-eastern/series` + `@ocs-eastern/match-core`；`packages/*` 只能相对本地 import）的硬约束。

**四处应以第三冬为准，不要照 smol 改**：天气（`ttw/campaign/weather.ts` 四态地面 + 三态飞行 + `freezeRun`/`thawRun`/`aprilMudRun`/`ice` 冻融链，smol `rules/weather.ts` 只有「地面恒 good + 1d6 限飞」，且 `WEATHER_GROUND_ALWAYS_GOOD` 本身就是斯摩棱斯克专规）；战斗地形倍率与反坦克（`ttw/scorpion/combat-terrain.ts` 含 `freeze` 覆盖、`major-river` 分档 `[0.25,1/3,0.5]`、炮兵独立 RE、反坦克 2→1.5 降级，smol 的 `attackMultiplier` 只是查 TEC 拿单个倍率）；退却（`match/scorpion-retreat.ts` 232 行独立模块，ZOC 进入即 DG、逐格 `passableRetreatStep`）；命令去重与版本化（`packages/match-core` 的 `Command`/`MatchRecord`/`acceptCommand`，smol 完全没有这一层）。

## 补齐清单（按优先级）

**P0 公共地基**：① `modes.ts` 模式矩阵下沉（4 行 × 12 字段，`BASE_MODE_EFFECT`/`MODE_MARKER_EFFECTS`/`maMultiplier`/`resolveModeStats`）→ 可一次消掉 `scorpionMovementAllowance` 与 `combatStrength` 两处手写三元式；② 常量归位（`STACKING_LIMIT_RE`=10 现硬编码于 `scorpion-retreat.ts:228`、惊袭阈值 10/5 与突袭 9/6 硬编码于 `tables/ground-combat.ts`、空战 7/7/5 硬编码于 `tables/air.ts`）；③ `zoc.ts` 的 `projectsZoc`/`zocEntryEffect` 下沉；④ `legality.ts`（1194 行 29 导出）下沉，用 `checkLegality` 换掉 10+ 处 `throw new Error`；⑤ `RuleOutcome` 过渡层。

**P1 通规正确性缺口**：铁路运力池 + 装载/移动/卸载三段校验（`TASKS.md:41` 已列为未完成）；主动改轨；空军七步序列契约 `AIR_MISSION_STEP_IDS`；高炮 DRM 与任务损失表；空运装载/移交判定；损耗结果类型恢复 `allSteps`；补给阶段「建议 + 校验」双入口；燃料过期与覆盖；拆解/整合（待剧本确认）；战斗损失「强制 vs 选项」分离；可负担炮击列选择；SOP 步骤链。

**P2/P3**：推导链、日志回放、存档版本化、流程引导、单位候选集、规则错误文案、跑道与设施建造；补给缓存、可变增援/撤离、补员资源池、独占用时点日历按剧本定。

**补漏**：复核 `rules/` 全部 58 个文件后发现矩阵漏列四项 —— **突破 `breakout.ts`**（333 行，常量在 `rulesConstants.supply` 属通规分组，TTW 却完全缺失）、雾战 `fog.ts`（4.9 可选规则）、`normalize-supply-dumps.ts`、`play-area.ts`。

## 专规边界（不得移植）

`src/data/rules-constants.json` 的 `smolensk` 分组（28 个键）本身就是红线清单。三个最危险的文件：**`rules/timing.ts` 13 个常量全部来自 `rulesConstants.smolensk`**（`RANDOM_EVENT_FROM`=1941-07-19 等日期），整文件 import 就等于把 1941 年日期固化进通规；**`rules/rail-cap.ts`** 的 `RAIL_CAP_BEFORE/AFTER` 与 7-19 提升日期（运力池机制是通规、数值是专规）；**`rules/weather.ts`**（看着像通用函数，实为 1941 年 8 月晴朗专规）。

另外不得搬：`panzer-groups.ts`（`['guderian','hoth']` 分界线）、`red-air-force.ts`（2.2 苏军航空军分区，TTW 对应物是 `ttw/air/mission-permission.ts` 的 `sovietMissionRestriction`）、`nkvd.ts`、`victory.ts`（城市清单 + Intro 剧本）、`arrival.ts`（`SLOW_MOBILIZATION_ARMY` 与到达日程表）、`hedgehog.ts` 的 `getPrintedHedgehog`（印刷工事是地图数据）、`supply-cache.ts`、`variable-repl.ts`/`variable-exit.ts`、`setup*.ts`（1531 行初设）、`containers.ts`（盒号）、`entry-edges.ts`（边字母）、`security-needs.ts`（城市表）。
