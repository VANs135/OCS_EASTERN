# 《第三冬》项目交接与干净检出指南

更新日期：2026-11-20。适用仓库：`VANs135/OCS_EASTERN`，默认分支 `main`。本文件按当前仓库状态维护；更早的检查记录和阶段方案保留为历史记录，以 `TASKS.md` 和当前代码为准。

## 接手结论

只拿到仓库即可开始规则引擎、专规和视图模型开发。源代码、依赖锁定文件、200 项自动化用例、第三冬专规与剧本资料快照、瓶中蝎地图几何、初设、增援、整理版单位库和 OCS v4.3 查表数据均在版本控制内。

仓库不是可直接安装游玩的完整桌面发行包。Windows 本地热座窗口代码已提交，但完整地图画面和实体算子显示需要项目方单独提供地图扫描图、辅助卡图、算子面图及配套第三冬数据库。仓库没有这些图像，也没有安装包或联网对局服务。引擎规则开发不依赖这些素材；桌面实库验收需要它们。

## 从干净检出开始

需要 Git、Node.js 22.12 或更新的 Node 22 版本，以及 npm。Windows 上 npm 工作区会在 `node_modules` 建立本地目录链接；若系统策略禁止链接创建，先启用 Windows 开发者模式或使用具备创建目录链接权限的开发环境。

```powershell
git clone https://github.com/VANs135/OCS_EASTERN.git
Set-Location OCS_EASTERN
node --version
npm --version
npm ci
npm run check
```

`npm run check` 会验证包边界、TypeScript 类型和全部自动化用例。2026-11-20 在仓库工作副本执行通过：200 项通过、0 项失败。首次安装需能从 npm 注册表取得锁定依赖。

本仓库目前没有单独打包桌面安装程序的命令。开发时直接运行工作区源码即可。

## 实库资料与桌面运行

`data/scorpion-real-library/` 内含经项目方整理的 JSON 快照：小地图格和格边、瓶中蝎标定、开局初设、增援、陆军/空军/标记算子，以及 OCS v4.3 战斗、炮击和设施射击表。其说明文件记录数据来源和已知待核项。不要把 `river_state: pending` 改成推断值。

桌面窗口还会读取项目方授权交付的视觉素材和配套数据库，包括原版地图和辅助卡扫描图、被引用的算子图，以及最新版第三冬地图/单位数据。它们通常由用户本机资料目录提供，不能通过仅克隆公共仓库获得。把外部资料路径传给启动命令即可：

```powershell
$ttwRoot = 'E:\OCS资料\第三冬'
$unitRoot = 'E:\OCS资料\DATA备份'
npm run play:local --workspace=@ocs-eastern/third-winter -- $ttwRoot $unitRoot
```

若只使用默认目录下的 v2 算子库，可省略 `$unitRoot`。程序会在本机 `dist/scorpion-local/` 维护设置和存档；`dist/` 不纳入 Git。图表默认读取仓库运行目录 `dist` 中的 JSON 快照。桌面窗口、图片素材和外部数据库首次运行还需在项目方 Windows 环境进行验收。

`audit:data` 面向本机完整第三冬数据库，不等同于仅仓库自动化检查。小剧本审计可用 `--scorpion-only` 避免读取战役地图文件：

```powershell
npm run audit:data --workspace=@ocs-eastern/third-winter -- $ttwRoot $unitRoot --scorpion-only
```

`preview:map`、`test:local` 和 `test:local:full` 也要求可读取前述桌面图像素材。其命令格式和详细步骤见 `games/third-winter/README.md`。

## 关键用户裁定

详细引用位置见专规梳理及开发记录；以下是继续开发时不可丢失的瓶中蝎口径：

- 苏军两骰合计 8 的可变补给按剧本地图给 7 SP。
- 第 1 / 第 2 乌克兰方面军炮击标记按小地图 S9 分区，S8 及以西为第 2 方面军，S9 及以东为第 1 方面军。
- 小地图外空军盒覆盖整张小地图，可作为被夺机场内幸存飞机的紧急位移落点；图上机场与空军盒转场按普通航程，轴心航空队指挥范围覆盖整张小地图。
- 空运中止时飞机受损则货物随剩余运力处理；飞机未受损时货物保留。无机场的空投目标遭拦截而中止时，货物随飞机损失。
- 只有苏联近卫军空降兵第 1 旅具备规则空投资格；其他带空降/伞兵番号的单位不因此获得空降能力。
- 通常格不持久记录控制。开局战线用于确定卸车格、补给源及剧本指定地点的初始归属；铁路归属按轨距和单位/控制区对连通性的影响处理。
- 守方战斗具象补给按整堆支付，并依 OCS 12.10h 分别处理多个小单位与单个多 RE 单位的余量。

## 接手后建议顺序

1. 先运行 `npm ci` 和 `npm run check`，记录 Node/npm 版本及实际结果。
2. 阅读 `TASKS.md`、当前桌面 UI 接口文档和专规梳理，选定一个未完成项作为首个改动。
3. 从对应机制测试开始理解规则，再沿“命令 → 会话 → 规则结算 → 视图投影 → 桌面交互”追踪实现。
4. 需要实库或桌面验收时，确认数据库版本与素材授权，并用独立存档测试。
5. 新增机制后更新测试、任务清单和相关说明；保持共享包与本作边界检查通过。
